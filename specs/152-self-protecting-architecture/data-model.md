# Data Model: Phase 11 Protection Contracts

This feature adds no runtime data model. It tightens relationships among three
existing authored records.

## Entity 1 - Capability ownership record

Source: `docs/capabilities/capabilities.yaml`

Relevant fields:

| Field | Meaning | Constraint added by Spec 152 |
| --- | --- | --- |
| `id` | stable capability identity | nonblank existing contract |
| `ownership.capability_owner` | closed owner token | existing O9 contract |
| `ownership.upstream_project` | upstream owner/project, when applicable | if nonblank and owner starts `seshat-`, delta is required |
| `ownership.seshat_delta` | concrete responsibility retained by Seshat | nonblank string for every upstream-backed Seshat owner |
| `references.skill` | canonical repo skill identities | for `speckit-workflow-skills`, derives provenance scope |

Invariant:

```text
capability_owner starts with "seshat-"
AND upstream_project is nonblank
=> seshat_delta is a nonblank string
```

The pre-existing invariant remains:

```text
capability_owner == "seshat-adapter"
=> seshat_delta is a nonblank string
```

## Entity 2 - Claude integration provenance manifest

Source: `.specify/integrations/claude.manifest.json`

Relevant fields:

| Field | Meaning | Constraint |
| --- | --- | --- |
| `integration` | harness identity | exactly `claude` |
| `version` | Spec Kit version claim | equals both other recorded version claims |
| `installed_at` | historical install timestamp | preserved; not regenerated by this feature |
| `files` | repo-relative path -> normalized SHA-256 | exact closure of the fourteen capability-referenced Spec Kit skills |

Path derivation for each capability skill name `N`:

```text
.claude/skills/N/SKILL.md
```

No path is accepted when blank, absolute, traversal-bearing, symlinked,
untracked, missing, or not a regular file.

## Entity 3 - Spec Kit initialization options

Source: `.specify/init-options.json`

Relevant field: `speckit_version`.

Version invariant:

```text
init-options.speckit_version
== claude.manifest.version
== speckit.manifest.version
```

## Authority boundaries

- The capability manifest owns **which skills belong to the capability**.
- The Claude manifest owns **which bytes were installed for those skills**.
- Init options and existing manifests jointly record **which upstream version
  was invoked**.
- The contract test owns no data; it only reconciles the three records.

## Failure states

The verifier returns a non-empty problem list for constructible tests. It does
not repair files, update hashes, infer owners, or grant approval.

Problem classes: scope mismatch, unsafe path, untracked/non-file path,
malformed hash, hash mismatch, malformed manifest, and version mismatch.
