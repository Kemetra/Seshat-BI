# Seshat BI -- v0.7 release candidate

This candidate records the changes merged after the frozen v0.6.1 release note.
It does not rewrite the historical claims captured in `docs/releases/v0.6.md` or
`docs/releases/v0.6.1.md`.

The full per-entry detail (with spec and PR citations) lives in `CHANGELOG.md`;
this note summarizes the shape of the release.

## What this release adds

- **The analyst-narrative layer (spec 021).** A judgment layer between semantic
  model readiness and dashboard layout: the `bi-analyst-knowledge` skill pack
  (derivation route from approved contracts + committed profile to ranked
  decision-questions, eight domain-neutral framing cards, a story-order rule),
  the frozen `seshat.narrative-brief/v1` schema, and `seshat narrative-check` --
  an offline, read-only checker enforcing grounded-only MEASURE cites, fresh
  contract revisions, story-order coverage, and the overview-headline comparison
  rule. Its `--binding-map` mode checks the three-way binding map
  (visual -> contract -> decision-question) against `seshat.binding-map/v1`,
  finding orphan visuals in either direction, unanswered decision-questions,
  pages serving no owner decision, and bare-total headline visuals.
- **`seshat reset <table>`** -- complete atomic teardown of one table's derived
  file-set, so a mis-onboarded table can be removed without hand-surgery across
  the mapping, dbt, and design surfaces.
- **`seshat pbi-mcp` read-only doctor family** (`detect`, `recommend`,
  `generate-config`, `preflight`) plus the F016 adapter contract and ADR 0018
  draft un-parking the Power BI MCP execution adapter. Read-only; executes
  nothing against Power BI.
- **`seshat pbir-validate-bindings`** -- an offline PBIR binding-resolution
  validator, and **`seshat adopt-pbip` measure-sync** -- governed measure upsert
  into adopted PBIP models, with documented gates and refusal conditions.
- **`seshat scaffold-design`** -- materializes the Stage-6/7 design and handoff
  templates into a workspace, so package-only (pipx / marketplace) users have
  templates to copy.

## What this release changes

- The `dashboard-design` skill is now **narrative-gated**: it STOPs unless a
  committed narrative brief exists before any layout guidance, and its binding
  map is upgraded from two-way to three-way. This arms enforced behavior on
  already-shipped skills.
- **Hardened Dagster and semantic/readiness boundaries** (2026-07-22 main review
  remediation): semantic readiness now depends on a validated approved-contract
  inventory whose L3 gate requires a `metric_owner` approval naming each base
  contract; redaction always precedes truncation and serialization; child
  processes receive a positive environment allowlist rather than an ambient
  `os.environ` copy; run evidence rejects dirty evidence. No stage is ever
  changed to `pass` and no readiness approval is self-granted.

## What this release fixes

A batch of fail-closed and fail-open correctness fixes across the static gate
and CLI surface -- among them `seshat check` no longer crashing on
tracked-but-unstaged deletions, S4b no longer false-flagging a schema-qualified
`ALTER COLUMN` inside a transaction, `dashboard-gaps` no longer failing open on
an unusable `--page-intent`, `dbt scaffold` failing closed on dropped-column and
model-name collisions, and `narrative-check`'s revision guard resolving
contracts in the real `metrics/` store instead of a directory no workspace
ships. See `CHANGELOG.md` for the full list with citations.

## Honest boundaries

- `seshat narrative-check`, `pbir-validate-bindings`, and the `pbi-mcp` doctor
  family are all **offline and read-only**: they execute nothing against Power BI
  and grant no approval. Live checks remain `[PENDING LIVE PROFILE]` without a
  reachable DSN and driver.
- `narrative-check` v1 does not ground dimension cites: the frozen
  dotted-dimension grammar does not match the bare-column profile format, and
  reconciling them is a follow-up owner decision.
- ADR 0018 (Power BI MCP execution adapter) ships as a **draft**; PBIR creation
  still requires an owner-ratified ADR and owner-supplied samples.
- This candidate does not itself create a tag, publish to PyPI, create a
  GitHub Release, or submit to public Claude, Codex, or OpenAI catalogs.
