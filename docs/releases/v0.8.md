# Seshat BI -- v0.8 release candidate

This candidate records the changes merged after the frozen v0.7.1 release note.
It does not rewrite the historical claims captured in `docs/releases/v0.7.md`,
`docs/releases/v0.7.1.md`, or any earlier note.

The full per-entry detail (with spec and PR citations) lives in `CHANGELOG.md`;
this note summarizes the shape of the release.

## Why this is a minor release, not a patch

v0.7.1 was a single-fix patch (it carried the inspector fix forward onto a
publishable version). This candidate carries **61 commits** -- 13 `feat`, 19
`fix`, plus docs/refactor/build work -- and adds a **new CLI verb**
(`seshat tmdl-doc-comment-lint`) along with new machine-written evidence and
several new advisory surfaces. That is a feature release.

## Why cutting this release matters (issue #494)

Two changes on `main` are **invisible to every installed user** until this
release publishes, which is the substance of the still-open issue #494:

- `21f5a77` (PR #503) ships `seshat tmdl-doc-comment-lint`. On an installed
  0.7.1 the verb does not exist -- `seshat tmdl-doc-comment-lint --help` reports
  `invalid choice`.
- `0aeb7e9` narrows two over-claiming validators. On an installed 0.7.1,
  `powerbi-workflows/SKILL.md` still reads as pre-Desktop clearance and
  `seshat pbir-validate-bindings` carries no TMDL caveat.

So an installed user still hits #494 exactly as reported: the guidance implies a
clean binding report means Desktop will load the model, and no headless check
catches the `///`-followed-by-blank-line defect that makes Desktop reject a whole
project with `DataModelLoadFailed`. The fix exists; it has not shipped.

**#494 closes only after this publishes** and the three checks above are
re-verified on a fresh `pipx install seshat-bi`.

## What this release adds

- **A headless TMDL doc-comment lint (`seshat tmdl-doc-comment-lint`, #494).**
  Checks exactly ONE rule: a `///` documentation block must be followed by a
  declaration, never a blank line or end-of-file. Deliberately narrow, and
  deliberately **not** named `tmdl-validate` -- full-fidelity TMDL validation
  needs the `TmdlSerializer`/TOM path that ADR-0001 excluded to keep this
  toolchain headless. Its output repeats the boundary on every run, including a
  passing one: **a pass does not mean Power BI Desktop can load the model.**

- **Machine-written, server-confirmed live-DB provenance (#485, A2).**
  `seshat validate` can now write a committed provenance record whose identity is
  echoed by the server, so live readiness evidence can be correlated with the
  database it was actually earned against. The earlier hand-authored option was
  rejected as forgeable from `.env` without opening a socket.

- **Two new advisory surfaces.** Shadow-vs-migrations column-shape drift (#492)
  is reported as a distinct advisory finding **outside** the parity enum, leaving
  ratified ADR-0009 intact. And `seshat next` now surfaces the orchestration
  adapter checkpoint and the canonical source-map shape at the stages where those
  decisions are actually made (#488, #489) -- informational signposts that never
  block, never change `outcome`, and grant nothing.

- **Expanded public knowledge layers.** Analyst-narrative reasoning, governed KPI
  decision packets, DAX semantic diagnostics, PostgreSQL plan reasoning, Python
  dataframe/validation routes, Big Data operational evidence, and standardized
  inbound/outbound handoffs across all six layers.

- **A Stage-6 narrative-brief blank (#514).** `templates/narrative-brief.md`
  now ships and `seshat scaffold-design` materializes it, so a pip-only workspace
  has the FIRST Stage-6 artifact to fill. The template states the boundary as
  DECIDING vs WRITING: the agent authors the brief via the
  `bi-analyst-knowledge` derivation route, and may transcribe a review a named
  human actually gave; it never invents that review or supplies the reviewer's
  name, never treats a clean `narrative-check` as approval, and never sets a
  readiness stage.

## What this release fixes

- **`narrative-check` validates the frozen v1 schema it claims to enforce**
  (#474): all required keys and types, contract-to-question linkage, malformed
  entries named rather than silently filtered, and adversarial tests for every
  reported reproduction.
- **Install and run commands that work in the documented pipx lane** (#507,
  #510, #513): the emitted commands now modify an existing install rather than
  replacing it, and enabling an extra no longer replaces the installed build.
  `seshat mcp` shows the install hint instead of a raw traceback.
- **Fail-open repairs.** An unreadable source-map is now reported instead of
  silently dropped (#508, #511); a `verified` live state requires the committed
  run record (#493); an unresolvable `gold_placement` prefix now ERRORs instead
  of being indistinguishable from a deliberate no-op (#499).
- **One shared resolver for a date dimension's attributes** (#491, #497), so the
  planner and the gap detector cannot disagree about which columns exist.
- **PBIR binding validator names what it cannot classify** (#475), and measure
  sync compares measure names case-insensitively (#476).

## Known limitations carried forward

- **Live publish to a Power BI workspace remains the deferred F016 adapter.**
  `publish_ready` is a readiness/approval verdict, never a live push.
- **`seshat tmdl-doc-comment-lint` is one rule, not a validator.** It says
  nothing about any other TMDL syntax and is not pre-Desktop clearance.
- **`cites.dimensions` is not ground-checked** in `seshat.narrative-brief/v1`.
  Resolving a dotted semantic-model reference against the bare source columns in
  a committed profile needs a third artifact the frozen two-input rule forbids;
  the checker states the limit rather than faking a grounding it cannot verify.
  Closing it needs a schema revision, which is an owner decision.
- **Open approval-request documents are not auto-discovered** (issue #517).
  `seshat approvals` reads only `mappings/*/readiness-status.yaml` and
  `seshat next` reads only the seven-stage spine; neither scans
  `approval-request-*.md`. Surfacing them needs a ruling on whether a second
  approval-trust path may exist beside the authoritative `approvals[]` one.
- **The `retail_store_sales` worked example is not yet migrated** to a real
  narrative brief plus `seshat.binding-map/v1` (issue #514). That migration
  re-signs a signed artifact and is owner-gated;
  `test_real_worked_example_map_still_needs_phase_b_migration` pins the current
  fail-closed state on purpose.

## Release mechanics (for whoever fires the dispatch)

- Cut via the `prepare-coordinated-release` dispatch with this note as its input.
- The release PR must **merge-commit, never squash**.
- Bot-authored release PRs get `ci`/`dep-integrity` **withheld**, so a single
  green check can hide a BLOCKED state -- assert a check **count**, not "1 green",
  and `gh run rerun` if checks are missing.
- The artifact inspector runs at **dispatch**, not post-tag, so a block costs a
  dispatch rather than a version number. It needs `twine`; pre-flight in a
  runner-like venv first.
- `v*` tags are immutable under the repository ruleset: a tag that fails the
  inspector can never be moved, and that version is permanently unpublishable
  (this is why v0.7.0 does not exist on PyPI).
