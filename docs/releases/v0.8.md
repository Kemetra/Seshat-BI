# Seshat BI -- v0.8 release candidate

This candidate records the changes merged after the frozen v0.7.1 release note.
It does not rewrite the historical claims captured in `docs/releases/v0.7.md`,
`docs/releases/v0.7.1.md`, or any earlier note.

The full per-entry detail (with spec and PR citations) lives in `CHANGELOG.md`;
this note summarizes the shape of the release.

## Why this is a minor release, not a patch

v0.7.1 was a single-fix patch (it carried the inspector fix forward onto a
publishable version). This candidate carries **199 commits across 49 merged pull
requests** -- 158 non-merge commits, of which 42 are `feat`, 51 `fix`, 39 `docs`,
15 `refactor`, and the remainder `chore`/`build`/`test`/`revert`.

It adds **six new CLI verbs** -- `seshat xray`, `seshat model-diff`,
`seshat readiness-diff`, `seshat cvd-evidence`, `seshat analyze`, and
`seshat tmdl-doc-comment-lint` -- and takes the packaged Claude and Codex
bundles from **11 skills to 21**. Every one of those is additive: a consumer
pinned to 0.7.1 keeps passing until they touch a newly-covered surface. That is
the MINOR row of `docs/operations/versioning-policy.md`.

**One change is a judgment call, and it is disclosed rather than buried.** HR1's
`gold_placement` resolution now ERRORs on an unresolvable prefix where it
previously returned `{}` silently (#499, #505), which can newly fail a repo that
was passing only because the resolution was empty. The owner classified this
under the policy's bug-fix-restores-intended-behavior row and kept the release
MINOR. See the `Changed` section of `CHANGELOG.md` for the consumer-facing
detail.

## Why cutting this release matters (issue #494)

Changes on `main` are **invisible to every installed user** until this release
publishes, which is the substance of the still-open issue #494:

- `21f5a77` (PR #503) ships `seshat tmdl-doc-comment-lint`. On an installed
  0.7.1 the verb does not exist -- `seshat tmdl-doc-comment-lint --help` reports
  `invalid choice`.
- `0aeb7e9` narrows two over-claiming validators. On an installed 0.7.1,
  `powerbi-workflows/SKILL.md` still reads as pre-Desktop clearance and
  `seshat pbir-validate-bindings` carries no TMDL caveat.

So an installed user still hits #494 exactly as reported: the guidance implies a
clean binding report means Desktop will load the model, and no headless check
catches the `///`-followed-by-blank-line defect that makes Desktop reject a whole
project with `DataModelLoadFailed`. The fix exists; it has not shipped.

**#494 closes only after this publishes** and the checks above are re-verified on
a fresh `pipx install seshat-bi`.

The same argument now applies to the ten compass verbs (below): the kit's own
orientation text names them, and until this release publishes, an installed
plugin does not carry them.

## What this release adds

- **PBIP X-Ray -- `seshat xray` and `seshat model-diff` (#549, #550, #551).**
  The largest feature in this release. `xray` builds a model graph by resolving
  measure and column references across parsed TMDL, reads PBIR visual bindings,
  and reports findings X0-X4 over the graph. `model-diff` classifies TMDL changes
  as semantic, cosmetic, additive, or removed -- so a reviewer can tell a
  formatting change from a change in what the model means. Supporting work
  extended the TMDL parser with relationship endpoints, cardinality, and
  measure/column metadata. Ships with a `pbip-xray` skill front door, a
  capability-inventory entry, and compass routing. **Advisory and read-only:**
  neither verb grants an approval, moves a readiness stage, or emits a confidence
  score.

- **The ten compass verbs now ship in the packaged bundles (spec 138 US2+US3,
  #547, #548).** The Claude and Codex bundles previously carried 11 skills and
  none of the ten compass verbs the kit's orientation text names. They now carry
  21, behind a portability gate, with the capability inventory as the authored
  source of what ships. The plugin also declares the read-only governor (US1),
  backed by the shipped `src/seshat/allowlist_derivation.py`. **Spec 138 remains
  partially implemented** -- US2 and US3 delivered; the spec is not complete, and
  this note does not claim it is.

- **A headless TMDL doc-comment lint (`seshat tmdl-doc-comment-lint`, #494).**
  Checks exactly ONE rule: a `///` documentation block must be followed by a
  declaration, never a blank line or end-of-file. Deliberately narrow, and
  deliberately **not** named `tmdl-validate` -- full-fidelity TMDL validation
  needs the `TmdlSerializer`/TOM path that ADR-0001 excluded to keep this
  toolchain headless. Its output repeats the boundary on every run, including a
  passing one: **a pass does not mean Power BI Desktop can load the model.**

- **A governed statistical evidence engine (`seshat analyze`, #529).** A locally
  executable Product Module with eight closed methods, strict schemas, immutable
  derived evidence, deterministic pending-human review, a fail-closed local CSV
  provider, and a PostgreSQL-only read-only Gold adapter. This supersedes the
  former universal statistical/forecasting exclusion. Autonomous ML/deployment
  and causal claims remain excluded, and **no result grants approval or changes
  readiness.**

- **Three further read-only surfaces.** `seshat readiness-diff` compares
  committed readiness state across two git revisions (#536); `seshat cvd-evidence`
  renders colour-vision-deficiency simulation evidence for one theme (#541); and
  `seshat profile` now accepts a landed CSV/TSV/Excel file, not only a DB table
  (#535).

- **Machine-written, server-confirmed live-DB provenance (#485 A2, #512).**
  `seshat validate` can now write a committed provenance record whose identity is
  echoed by the server, so live readiness evidence can be correlated with the
  database it was actually earned against. The earlier hand-authored option was
  rejected as forgeable from `.env` without opening a socket.

- **Readiness blockers name who acts on them** (#538), from a committed
  allowlist -- so a blocker routes to a person rather than sitting unowned.

- **Advisory signposts.** Shadow-vs-migrations column-shape drift (#492, #501) is
  reported as a distinct advisory finding **outside** the parity enum, leaving
  ratified ADR-0009 intact. `seshat next` surfaces the orchestration adapter
  checkpoint and the canonical source-map shape (#488, #489, #506), and open
  approval requests via the authoritative path (#517, #522). These never block,
  never change `outcome`, and grant nothing.

- **Expanded public knowledge layers (#496).** Analyst-narrative reasoning,
  governed KPI decision packets, DAX semantic diagnostics, PostgreSQL plan
  reasoning, Python dataframe/validation routes, Big Data operational evidence,
  and standardized inbound/outbound handoffs across all six layers.

- **Drift-proofing.** The agent-facing rule fix table is now generated from the
  registered rules (#543), the spec status vocabulary is closed and implemented
  claims locked (#544), and acceptance transcript fixtures are bound to the
  bundle they exercised (#542).

## What this release fixes

- **Connection-string redaction** now redacts by SPAN rather than substring
  fragment, redacts quoted values whole, and keeps punctuation inside bare libpq
  conninfo values (#527, #528). Five further reviewed security findings closed --
  fail-opens, git-hardening drift, and the DSN wrapper.
- **Install and run commands that work in the documented pipx lane** (#507,
  #510, #513): the emitted commands modify an existing install rather than
  replacing it, and enabling an extra no longer replaces the installed build.
  `seshat mcp` shows the install hint instead of a raw traceback.
- **Fail-open repairs.** An unreadable source-map is reported instead of silently
  dropped, and HR1 degrades like HR13 on one (#508, #511); a `verified` live state
  requires the committed run record (#493, #504).
- **One shared resolver for a date dimension's attributes** (#491, #497, #502), so
  the planner and the gap detector cannot disagree about which columns exist.
- **Gate hardening** (#474-#477): `narrative-check` validates the frozen v1 schema
  it claims to enforce, the `pbi-mcp` preflight binds to its declared target and
  transport shape, the PBIR binding validator names what it cannot classify, and
  measure sync compares measure names case-insensitively.
- **Power BI theme token and preview fidelity** (#520, #521, #523-#526): dark-seed
  derivation, non-text ground compositing, the tokens degrade split, transparency
  validated at the gate, collisions no longer misattributed, and malformed tokens
  rejected.

## Genericity evidence, not shipped runtime

**Spec 137 -- the Finance GL genericity proof (#545, #546)** landed a
deterministic Finance GL fixture generator, 9 defect variants, 6 judgment
scenarios, a full set of mapping artifacts stopped at the gate, a genericity
ledger, and a defect matrix.

This is deliberately called out as **evidence, not a shipped feature**: it landed
under `mappings/`, `docs/worked-examples/`, and `benchmark/scenarios/`, with no
change to `src/seshat/`. An installed user gains no new behavior from it. It
exists to demonstrate the engine is not retail-specific.

## Known limitations carried forward

- **Live publish to a Power BI workspace remains the deferred F016 adapter.**
  `publish_ready` is a readiness/approval verdict, never a live push.
- **`seshat tmdl-doc-comment-lint` is one rule, not a validator.** It says
  nothing about any other TMDL syntax and is not pre-Desktop clearance. Issue
  #494's broader TMDL-validation gap stays open.
- **`seshat xray` and `seshat model-diff` are advisory.** A clean X-Ray is not an
  approval, not a readiness stage, and not a statement that the model loads in
  Desktop.
- **Spec 138 is partially implemented.** US2 and US3 shipped; the spec is not
  closed.
- **`cites.dimensions` is not ground-checked** in `seshat.narrative-brief/v1`.
  Resolving a dotted semantic-model reference against the bare source columns in
  a committed profile needs a third artifact the frozen two-input rule forbids;
  the checker states the limit rather than faking a grounding it cannot verify.
  Closing it needs a schema revision, which is an owner decision.
- **`approval-request-*.md` documents are still not scanned** (issue #517).
  `seshat next` now surfaces open approval requests via the authoritative
  `approvals[]` path (#522), but a dedicated document scanner was deliberately
  reverted as out-of-scope and fail-open. Adding one needs a ruling on whether a
  second approval-trust path may exist beside the authoritative one.

## Release mechanics (for whoever fires the dispatch)

- Cut via the `prepare-coordinated-release` dispatch, `version=0.8.0`, from
  `main`. It projects the version, freezes `[Unreleased]` into `## [0.8.0]`, and
  opens a draft PR on `release/v0.8.0`.
- The release PR must **merge-commit, never squash**. Squash and rebase are both
  enabled on this repository, so the merge method has to be chosen explicitly --
  either loses the projection commit that bundle provenance records.
- Bot-authored release PRs get `ci`/`dep-integrity` **withheld**, so a single
  green check can hide a BLOCKED state -- assert a check **count**, not "1 green",
  and `gh run rerun` if checks are missing.
- The artifact inspector runs at **dispatch**, not post-tag, so a block costs a
  dispatch rather than a version number. It needs `twine`; pre-flight in a
  runner-like venv first.
- When dispatching `release-candidate` to publish, `candidate_ref` must be the
  literal string `refs/tags/v0.8.0` and the dispatch ref must be that same tag.
  The publish job asserts `github.ref == candidate_ref`; a bare `v0.8.0` passes
  build-validate and then fails publication **after** the tag exists.
- `v*` tags are immutable under the repository ruleset: a tag that fails the
  inspector can never be moved, and that version is permanently unpublishable
  (this is why v0.7.0 does not exist on PyPI).
