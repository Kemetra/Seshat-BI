# Seshat BI -- v3.0

This note summarizes the changes merged after v2.1.0. The complete per-entry
record, with pull-request references, lives in `CHANGELOG.md`.

## Why this is 3.0 and not 2.2

Read this before anything else in this note.

**This is a MAJOR bump because existing rule ids and CLI contracts now judge an
unchanged repository differently, not because the kit grew.** The release is almost
entirely the 2026-09 expert-board audit remediation (#752--#763, #776). Nearly every
fix in it closes a fail-open: a gate that passed on an absent, uncommitted, or
unparseable input now refuses. `docs/operations/versioning-policy.md` classifies a
rule whose behavior changes so that it "can newly fail a previously-passing repo" as
MAJOR, and an exit-code meaning change as MAJOR. This range lands in both rows:

1. **Existing rules got stricter.** RS1 rejects wrong-class stage approvals and
   out-of-order passes, and prose-only contract approvals no longer bind (#763). C2
   flags more secret shapes (#758). P2 judges `HEAD` on a single-commit repository
   (#758). A rule that raises is now an ERROR finding (#753).
2. **Existing CLI contracts changed.** `seshat reset` refuses a dirty tree (#756).
   `pbi-mcp` preflight blocker ids changed meaning (#761). Statistical evidence renames
   `epsilon_squared` to `eta_squared_h` (#759).
3. **Approval-bearing surfaces read committed state.** Approvals no longer advance a
   stage outside git or from an uncommitted readiness file, and a project nested inside
   another git root fails closed on report render, analyze, the coordinator and
   measure-sync (#756, #763). The dbt and Dagster gates read committed state too (#760).

**What did NOT change is worth stating as plainly.** No `seshat check` rule id was
added, removed, or renamed: extracting every `@register(...)` id under
`src/seshat/rules/` gives the same 51 ids at `v2.1.0` and at the release commit.
Existing CLI verbs, flags and default exit codes remain in place; the additions
(`seshat next --exit-code`, three new `doctor --format json` keys) are opt-in or
additive.

## Migration

| If you | Do this |
|---|---|
| see RS1 newly fail | record each stage's approval from that stage's authority, and pass stages in order. `dashboard_ready` also accepts `governance` and `data_owner` for now |
| wrote contract approvals as prose ("approved contract X") | name them: `contracts: [X]` or `contracts: X, Y` |
| run Seshat on a project nested inside a larger git repository | commit the readiness and decision files; approval-bearing surfaces read `HEAD`, not the worktree |
| see C2 newly flag a file | untrack the secret-bearing file, or clear the filled `*_TOKEN`/`*_SECRET` value in `.env.example` |
| script `seshat reset` on a tree with local edits | commit or stash first, or pass `--discard-uncommitted` deliberately |
| parse `pbi-mcp preflight` blocker ids | re-map `GATE-01`/`GATE-02` and handle `PBIMCP-GATE-16`, `PBIMCP-EFF-03`, `PBIMCP-DRIFT-01` |
| read `epsilon_squared` from statistical evidence | read `eta_squared_h` |
| hold an accepted dbt plan from before this release | re-plan once; plan digests now hash committed blobs |
| use reflog revisions such as `HEAD@{1}` in `--base`/`--head` | pass a commit SHA or a branch/tag name |

Do not pin to 2.1.0 to restore a green verdict. Each newly failing case is a gate that
was previously passing on evidence it could not verify.

## What else is in this release

### Studio

Studio decision records are DS1-valid, and a decline never authorizes apply (#755).
Each turn has its own Codex session state, and boundary redaction includes the
bare-token layer. The committed-state reader works for a workspace nested inside a
larger repository. The production turn context (business-approval reminder, requested
mode, readiness facts) now reaches Codex ahead of the prompt. Command approvals no
longer claim a scope or risk the provider did not state. Operations probes the Codex
adapter, frontend assets, package extras and the live boundary instead of reporting
them healthy. Abandoned turns are reaped on any poll, and an active session renews its
expiry on use.

The agent panel can bind a conversation to a table (#776). A technical Allow is
reachable only for an exact workspace read (`pwd`, `rg --files`) run from an absolute
working directory inside the workspace. `git status` is deliberately excluded: it runs
the workspace's own filesystem-monitor configuration. The Codex child no longer
inherits `RIPGREP_CONFIG_PATH`, so an allowed `rg --files` cannot follow a symlink out
of the workspace.

### Hardening across the kit

Every git call spreads the shared `GIT_HARDENING` flags, and paths are listed NUL-safely
(#753). Live-DB surfaces use one redaction chain (#757). The integrations firewall sits
at the mutation site, and `apply()` requires a committed approval (#762). The Power BI
MCP write preflight fails closed without a capability profile (#728), and its drift
gate fails closed at runtime (#761). Ambiguous routing terminates instead of looping
(#727).

### Finance gold

The finance model-integrity rulings A1/B1/C1 are recorded and their gold SQL applied
(#723), and the `finance_gl_actuals` gold_ready live validation pass is recorded
(#724). `UNIQUE` natural keys on the finance dimensions make a code with two attribute
values fail the load, where it previously fanned out and doubled budget rows (#754).
Follow-up migrations 0009 and 0010 must run after 0008 and 0004.

### Analytics correctness

Metric drift and portfolio watch fail closed, omega² uses the textbook form, and
proportion floors above 1 withhold small cells (#759).

## Honest boundaries

- **npm publishing still uses a long-lived `NPM_TOKEN`.** Trusted publishing must be
  configured on the registry for both package names first; this is owner-gated (#754,
  F218).
- **The Studio command allowlist matches a plain command string.** The Codex approval
  fixture is synthesised from the schema that `codex-cli 0.147.0` generates, not
  recorded live. If a live Codex wraps commands, for example `bash -lc '...'`, Allow
  stays unreachable. That fails closed.
- **A wheel install does not ship the `dagster-workflows` skill file** (#762). Outside a
  source checkout, `seshat-dagster-workflows` is unavailable unless the workspace
  vendors it; the adapter itself resolves from the package.
- **The Power BI MCP vendor is pinned exactly** (#761). If `0.5.0-beta.12` is
  unpublished, launch fails closed with `PBIMCP-RUN-03`.
- **`dashboard_ready` stage authority is deliberately loose** (#763). It accepts
  `governance` and `data_owner` alongside `report_owner` until the committed retail
  record is re-signed.
- **Plugin catalogs.** The in-repository Claude marketplace and Codex catalog carry
  this version. Nothing in this release submits to an external public catalog.

## Verification posture

Every PR in this range merged with the full CI suite (Linux and Windows unit lanes,
contract, integration, report and statistics lanes) green on its head. The audit
PRs each passed a pre-merge adversarial review. This note makes no public-install claim
by itself; PyPI, npm and GitHub Release availability are established by the release
