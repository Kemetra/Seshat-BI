> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two read-only verbs over one shared model graph — `seshat xray` (full-model audit of a committed PBIP semantic model) and `seshat model-diff --base <ref>` (PR-scoped semantic diff) — per the approved spec `docs/superpowers/specs/2026-08-01-pbip-xray-design.md`.

**Architecture:** A new `src/seshat/xray/` package builds a frozen `ModelGraph` from the EXISTING TMDL parser (`src/seshat/tmdl.py`), enriched by a small backward-compatible parser extension (relationship endpoints/cardinality/activity, measure format/description, column sortBy). PBIR JSON is walked recursively for visual bindings. Audit findings (X0–X4) and the semantic diff are pure functions over that graph. CLI mirrors `src/seshat/cli/commands/analyze.py`'s envelope.

**Tech Stack:** Python 3.13, stdlib only (re, json, dataclasses, pathlib, subprocess via existing `gitutil.git_output`). pytest with `@pytest.mark.unit`.

**Execution note (owner decision 2026-08-01):** Execution is DEFERRED. This round ships spec + plan + PR only. When executed: implementation agents run on **Opus**, review passes on **Fable**.

## Global Constraints

- Read-only observer: NEVER writes to the repo, never opens a DB connection, never touches the Power BI execution adapter (F016). The diff base side uses `git show <ref>:<path>` — no checkout.
- Advisory authority: findings NEVER fail the process. Exit code 0 when the audit ran (regardless of findings); exit 3 only when the verb could not run (blocker payload, `analyze.py` envelope shape).
- NO numeric health/quality score anywhere (hard principle: never fabricate a confidence score). Counts and findings only.
- NOT wired into the `seshat check` rule registry: no `@register`, no rule-count claims, no severity-posture entry, none of the 9 rule surfaces.
- Absence of evidence never becomes a finding: any unreadable/unparseable surface downgrades wording, never fires.
- Style: frozen dataclasses, type annotations on every signature, functions <50 lines, nesting <4 (CodeScene delta gate is a required PR check), files 200–400 lines.
- ASCII-only in all CLI output (Windows charmap). No `print` in library code (`src/seshat/xray/*`) — only the CLI command module prints.
- All new tests: `@pytest.mark.unit`, TMDL/PBIR fixtures as inline string literals (small), no fixture files needed (tests/ is rule-exempt via `is_test_path`).
- Local verification before push: `ruff format --check src/ tests/`, `ruff check src/ tests/`, `pytest -m unit -x -q` (use the scratch `GIT_CONFIG_GLOBAL` neutralizer for the 1Password signing wall in temp-repo tests), CodeScene `analyze_change_set`.

```python
_REL_ENDPOINT = re.compile(
    r"^(?:from|to)Column:\s*(?:'(?P<qt>(?:[^']|'')*)'|(?P<bt>[^.']+))"
    r"\.(?:'(?P<qc>(?:[^']|'')*)'|(?P<bc>\S+))\s*$"
)


def _endpoint(stripped: str) -> tuple[str, str] | None:
    """Parse ``fromColumn:``/``toColumn:`` into (table, column), or None."""
    m = _REL_ENDPOINT.match(stripped)
    if m is None:
        return None
    table = (m.group("qt") or m.group("bt") or "").replace("''", "'").strip()
    column = (m.group("qc") or m.group("bc") or "").replace("''", "'")
    return table, column
```

```python
# the resolver needs single-quoted table names intact, so it defines its own
# _strip_for_refs (comments + double-quoted strings only). The public stripper

# rules/dax.py for D4.

# 'Table Name'[Col], Table[Col], or bare [Name] — in that scan order.
_QUALIFIED = re.compile(r"(?:'(?P<qt>(?:[^']|'')*)'|(?P<bt>[A-Za-z_][\w ]*?))\[(?P<c>[^\]]+)\]")
_BARE = re.compile(r"\[(?P<n>[^\]]+)\]")
```

Recursive walk, schema-agnostic by design (PBIR nests these nodes at many depths; walking beats hardcoding paths). Core:

```python
def _walk(node: object, out: _Sink) -> None:
    if isinstance(node, dict):
        _capture(node, out)
        for value in node.values():
            _walk(value, out)
    elif isinstance(node, list):
        for item in node:
            _walk(item, out)


def _capture(node: dict, out: _Sink) -> None:
    column = node.get("Column")
    if isinstance(column, dict):
        ref = _entity_property(column)
        if ref is not None:
            out.columns.add(ref)
    measure = node.get("Measure")
    if isinstance(measure, dict):
        ref = _entity_property(measure)
        if ref is not None:
            out.measures.add(ref[1])
    level = node.get("HierarchyLevel")
    if isinstance(level, dict):
        ref = _hierarchy_level(level)
        if ref is not None:
            out.columns.add(ref)
```

`_entity_property(d)` digs `d["Expression"]["SourceRef"]["Entity"]` + `d["Property"]` (both required, else None). `_hierarchy_level(d)` digs `d["Expression"]["Hierarchy"]["Expression"]["SourceRef"]["Entity"]` + `d["Level"]`. `read_bindings` json-loads each file inside `try/except ValueError` (malformed → skipped silently — absence of evidence, not a finding); `report_scanned = True` iff at least one file was supplied (even if all malformed: the report EXISTS, bindings are just unknown — set `report_scanned=True` only when at least one file parsed; otherwise False. Encode this exact rule in a comment).

Finding rules (from the spec, made precise — the implementer codes EXACTLY these):
- **X0** (info): one finding per entry in `graph.parse_notices`.
- **X1 unused column** (warning when `bindings.report_scanned`, info otherwise): a column referenced by NO measure (`column_refs`), NO relationship endpoint, NO `sort_by_column` of a sibling column, NOT in `text_referenced_columns`, and — when scanned — NO visual binding. Hidden columns (`is_hidden`) that ARE relationship keys are exempt (standard modeling). Message wording when `report_scanned is False` MUST read `unreferenced in scanned surfaces (no report scanned -- visual usage unknown)`.
- **X1 unused measure** (same severity logic): a measure with no inbound `measure_refs` edge and — when scanned — not in `bound_measures`. When `report_scanned is False`, orphan-measure findings are INFO with the same downgraded wording (a measure's only legitimate consumer may be a visual).
- **X2 many-to-many** (warning): `from_cardinality == "many" and to_cardinality == "many"`.
- **X2 inactive-unused** (info): `is_active is False` and no measure expression contains `USERELATIONSHIP` (scan the comment-stripped expressions, case-insensitive).
- **X2 string keys** (info): both endpoints resolve to columns whose `data_type == "string"` (statically provable; cardinality itself is never guessed — say so in the message).
- **X2 snowflake** (info): a directed path of **3 or more relationship hops** (4+ tables) walkable following `from -> to` direction; report the deepest path once per starting table. Bi-di is NOT re-checked — D6 owns it; skip any relationship with `cross_filtering_behavior == "bothDirections"` and add no finding.
- **X3 depth** (info): measure whose reference chain depth >= 5 (DFS over `measure_refs`; cycles guarded by a visited set — a cycle itself yields one X3 warning `circular measure reference`).
- **X3 duplicate logic** (info): two measures whose `normalize_measure_body` outputs are identical (same as D3's normalization) AND that live in DIFFERENT tables (D3 already reports same-normalized duplicates generally — X3 adds the graph context; cite D3 in the message).
- **X4 unmarked date table** (info): a relationship endpoint column named like `%date%` whose table lacks the date marker (reuse `_table_is_marked_date_table` logic — REIMPLEMENT locally from `TmdlTable.data_category == "Time"` + any `is_key` column; do not import the private helper from `rules/dax.py`); message cites D7.
- **X4 default-summarized feeding nothing** (info): column with `summarize_by` not in (None, "none") that has no measure reference and no binding.
- Unresolved references (`graph.unresolved`) are EXCLUDED from every "unused" determination (conservative core).

```python
    bucket: str          # "semantic" | "cosmetic" | "additive" | "removed"

def diff_models(

    # base side from `git show`). Pure function, no git here.
```

Classification (exact):
- measure present both sides, `normalize_measure_body` differs → **semantic** `"measure logic changed"`; formatString/description/displayFolder-only change → **cosmetic**.
- column `data_type` changed → **semantic**; `summarize_by`/`sort_by_column`/`is_hidden` changed → **cosmetic**.
- relationship added/removed, or endpoints / `is_active` / cardinality / `cross_filtering_behavior` changed → **semantic** (a removed+added pair with identical endpoints but a new name counts as changed, matched by endpoint tuple, not by name — TMDL relationship names are GUIDs that churn).
- new measure/column/table at head → **additive** (sentence lists what it references, via a light `_QUALIFIED` scan); present at base, gone at head → **removed**.
- table matching is by table NAME; a renamed table = removed + additive (state this in the module docstring; rename detection is YAGNI).
